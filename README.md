# blissmom — 인스타그램 일별 대시보드

바탕화면 바로가기를 누르면 → 최신 데이터를 받아서 → 브라우저에 대시보드가 뜨는 개인용 도구입니다.
표준 라이브러리 + `requests` 만 사용합니다.

## ⚠️ 시작 전에 꼭 알아야 할 것

**총 팔로워 수는 과거 이력을 API가 주지 않습니다.** "지금 몇 명"만 알 수 있어서,
매일 `fetch.py`를 실행해 CSV에 하루치씩 쌓는 방식으로만 그래프를 그릴 수 있습니다.
**오늘 처음 실행하면 오늘이 1일차**입니다. 어제 이전 데이터는 만들어낼 수 없습니다.

## 처음 설정하는 방법

1. 이 폴더를 원하는 위치(예: `~/insta-dashboard`, `C:\Users\내이름\insta-dashboard`)에 둡니다.
2. `python -m venv venv` (선택) 후 `pip install -r requirements.txt` (즉, `requests`만 설치)
3. `config.example.json` 을 **`config.json`** 으로 복사하고 `access_token` 값을 채웁니다.
   - `ig_user_id` 는 비워두면 토큰으로 자동으로 찾아서 채워줍니다.
   - `daily_record_hour`: "하루의 공식 기록 시각"입니다. 기본 9시. 이 시각 이후 첫 실행에서만
     그날의 팔로워 수가 CSV에 기록되고, 이후 재실행은 값을 덮어쓰지 않습니다.
     (아침에 쟀다가 저녁에 또 재서 같은 날짜가 두 번 기록되는 걸 방지)
4. 한 번 수동 실행해서 확인:
   ```
   python fetch.py
   python build.py
   ```
   `dashboard.html` 이 생성되고 브라우저가 열립니다.
5. 바탕화면 바로가기 + 매일 자동 실행을 등록하려면, **사용자의 실제 PC에서**:
   ```
   python setup_shortcut.py
   ```
   - Windows: 바탕화면에 `.lnk` 생성 + 작업 스케줄러 등록 (콘솔 창 안 뜸, 절전이면 깨워서 실행,
     놓친 실행은 켰을 때 바로 실행)
   - macOS: 바탕화면에 더블클릭 앱(.app) 생성 + launchd 등록 (절전 중 놓친 실행은 깨어난 뒤 자동 실행)

## 화면 구성

- **일별 지표** 탭: KPI 카드(오늘 팔로워/기간 순증/일평균 순증/최고 증가일/발행 수),
  팔로워 성장 곡선(SVG, 마우스오버 툴팁), 월별 순증 막대(클릭하면 그 달만 필터),
  일별 표(날짜별 팔로워/도달/프로필방문/링크클릭 + 그날 발행 콘텐츠 썸네일·통계).
  월 필터, "발행일만" 토글, 콘텐츠 검색을 표 위 컨트롤에서 사용할 수 있습니다.
- **월간 리포트** 탭: 월별 카드가 최신순으로 쌓이며 순증·일평균·발행 수·포맷별(릴스/캐러셀/
  이미지/동영상) 1건당 3일 순증·평균 조회/도달/저장률·TOP3 게시물을 자동 계산합니다.
  `reports/2024-01.md` 처럼 만들어두면 그 달 카드 아래에 그대로 붙어서 보입니다
  (분석·다음달 계획은 사람이 직접 씁니다. `reports/2024-01.md.example` 참고).

## 데이터가 쌓이는 곳 (모두 git에는 올라가지 않음, `.gitignore` 처리)

- `data/daily_followers.csv` — 하루 1행, **공식 기록은 절대 덮어쓰지 않음** (장기 기록의 원본)
- `data/daily_account_metrics.csv` — reach/프로필방문/링크클릭 등 일별 지표, **30일 지난 행도 삭제 안 함**
- `data/media.json` — 게시물 목록 캐시 (누적 보관)
- `data/media_insights_cache.json` — 게시물별 조회/저장/공유 등 인사이트 캐시 (최근 3주만 갱신)
- `data/latest_reference.json` — "지금 이 순간" 팔로워 수 (참고용, 공식 기록에는 반영 안 됨)
- `thumbs/<게시물id>.jpg` — 썸네일을 파일로 저장 (인스타 서명 URL은 며칠 뒤 만료되므로)

## 반드시 알아둘 API 제약 (코드에 반영되어 있음)

- 계정 일별 지표는 **`reach`만 `period=day`로 시계열**을 줍니다. `profile_views`, `website_clicks`,
  `accounts_engaged`, `views`, `total_interactions`는 `metric_type=total_value`로 **하루 단위 1콜씩**
  호출해야 합니다 (하루 1콜에 5개 동시에 받음).
- 계정 일별 지표는 최근 30일까지만 제공 → 그래서 CSV에 누적하고 오래된 행을 지우지 않습니다.
- 게시물 인사이트는 지원하지 않는 지표가 하나라도 섞이면 응답 전체가 에러가 납니다.
  `fetch.py`는 넓은 지표 세트부터 좁은 세트로 낮춰가며(`views,reach,saved,shares,total_interactions`
  → … → `reach`만) 재시도하고, 성공한 값은 캐시에 저장해 다시 부르지 않습니다.
- 게시물별 `follows`/`profile_visits`는 API가 지원하지 않습니다. 대신 "발행일 기준 3일간
  팔로워 순증"으로 콘텐츠별 유입 효과를 근사합니다 (월간 리포트의 "포맷별 1건당 순증").
- 데이터 빠진 날은 화면에서 회색 점으로 표시하고 **보간된 값**임을 밝힙니다(앞뒤 값 사이 선형 보간,
  양쪽 다 아는 값일 때만). API가 아예 안 주는 구간(예: 계정 인사이트 30일 밖)은 빈 칸으로 둡니다.
- 마지막 공식 기록이 오늘이 아니면 대시보드 상단에 "N일 전 기준" 경고 배너가 뜹니다.

## 알려진 한계 (숨기지 않고 명시)

- 썸네일은 160px로 축소 저장하도록 안내받았지만, 의존성을 `requests`만으로 최소화하기 위해
  **리사이즈 없이 원본 그대로 저장**합니다 (Pillow 등 이미지 라이브러리 미사용). 게시물 수가
  많아지면 `thumbs/` 폴더 용량이 안내받은 "100장당 1MB"보다 커질 수 있습니다.
- 게시물 발행일은 인스타그램이 주는 타임스탬프의 날짜 부분(UTC)을 그대로 사용합니다.
  시/분 단위 시간대 보정은 하지 않습니다 (일별 대시보드 용도로는 충분하다고 판단).
- `reports/*.md`는 제목(`#`,`##`)·목록(`-`)·굵게(`**`)만 지원하는 아주 단순한 마크다운
  변환기로 렌더링됩니다 (외부 마크다운 라이브러리를 쓰지 않기 위함).
